# 0015: 窓の記号と丸の色を riml のものにする（参考にした画面と重ねない）

- 状態: Accepted
- 日付: 2026-09-20
- 関連: ADR-0013（「まど」）、ADR-0014（丸はボタン）、[brand.md §7.1 / §9](../brand.md)

## 文脈

ADR-0014 は帯の左端の丸を `<button>` にし、記号を「幾何（× / □ / −）を `mask` の data URI で描く」と決めた。
実装は `viewBox 0 0 16 16` / `stroke-width 2` の直線で、丸はすべて `chrome.text`（クリーム）の塗りだった。

オーナーから指摘が入った: **その 3 つの記号が参考にした画面のものに近すぎる。** 幾何の形（× / □ / −）は
ウィンドウ操作の共通語彙なので変えようがないが、**同じ角度・同じ太さ・同じ角丸・同じ一色の丸**で描けば、
見た目は参考元そのものになる。brand.md §9 は「絵・アイコン・ロゴ・キャラクター・文言を写さない」と書いていたが、
**記号の筆致**については何も言っていなかった。

riml のキャラクター（青髪・赤目・クリームの肌、髪に × の印）は既に色（§2）の出自になっている。
形の側にも同じ出自を通せる。

## 決定

1. **記号は幾何のまま、riml の筆致で描く。** `stroke-width` を 2.4 に太らせ、端は丸のまま
   （`stroke-linecap: round`）、× は **8 度傾け**（手で書いた印＝キャラクターの髪の × に寄せる）、
   □ は角丸を一辺の 1/3 弱（一辺 9.6 に `rx 3`）まで丸め、− は端を丸く短く取る。
   0.75rem に縮めても 1 本の線として読める太さを下限にする。
2. **丸の塗りは操作ごとに riml の 3 色にする。** 新しい semantic トークン
   `color.chrome.control.close` / `.expand` / `.collapse` を作り、それぞれ
   `danger.300`（ほっぺの桃）/ `accent.300`（髪の青）/ `neutral.0`（紙）を alias する。
   記号の色は `chrome.default`（帯の色）のまま。
3. **3 色は帯に対して 3:1 以上を全モード・全テーマで機械検査する。** `$extensions.riml-ds` に
   `contrastAgainst: color.chrome.default` と `nonText: true` を付ける。記号の色 = 帯の色なので、
   この 1 対で「丸 ↔ 帯」と「記号 ↔ 丸」の両方を見ていることになる。最も低い組で 5.84:1（dark）。
4. **色だけで操作を伝えない。** 3 色は記号と `aria-label` の**上に足す**目印で、置き換えではない。
   強制配色（`forced-colors: active`）では 3 色は消え、`ButtonFace` + `ButtonText` の輪郭に戻る（ADR-0014 のまま）。
5. **帯の `data-tone` を変えても丸の色は動かさない。** 丸は操作の目印であって帯の装飾ではない。

## 却下した案

- **記号を「表情」にする（× 目 / まんまる目 / にっこり目）**: いちばんキャラクターらしいが、
  「広げる」が丸、「たたむ」が弧になり、記号だけを見て操作を当てられなくなる。窓の操作は
  見慣れた幾何であることに価値がある（`better-ui`「見た目の約束を破らない」）。
- **すべてを × から作る（× / ◇ / ∨）**: 意味は通るが □ を捨てるほどの理由がない。
- **丸そのものの輪郭を変える（アホ毛付き・たまご型）**: 押せる丸の輪郭が不揃いになり、
  `forced-colors` で `ButtonFace` の円に戻したときに形が入れ替わる。
- **閉じるの丸を `signature.500`（赤の印）にする**: 帯のインクの上で 2.37:1 で、非文字 3:1 を割る。
  「赤・黄・緑の信号機」に見える点でも参考元に近づく。桃（`danger.300`、6.36:1）を採った。

## 影響

- 新規トークン 3 つ（112 → 115）。`terrazzo.config.ts` の `core/duplicate-values` の ignore を
  `color.chrome.*` → `color.chrome.**` に広げる（semantic の別名は値が重なってよい）。
- `_shared/window-chrome.ts` と `patterns.css` の data URI を 3 つとも差し替え、
  `--rd-window-control-color` を足す（既定は `chrome.text`、`[data-action]` ごとに上書き）。
  2 か所が同じ文字列であることは従来どおり `window-chrome.test.ts` が固定する。
- VRT: 窓・ダイアログ・Foundations/Mado の基準画像を撮り直す。**1024 幅では `--update-snapshots`
  （= `changed`）だけでは基準が入れ替わらない**——丸 3 つ分の色差（およそ 950px）が
  `maxDiffPixelRatio: 0.001`（786px）を下回り「差分なし」と判定されるため。
  色だけを変えたときは `bash scripts/vrt.sh --update-snapshots=all -g "<story>"` で撮り直す
  （360 幅は同じ差分が閾値を超えるので自動で入れ替わる）。
- 利用側（qrcc / noter）は追随不要（クラスと属性は変わらない。色と記号だけが変わる）。
