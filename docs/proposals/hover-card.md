# 提案: Hover Card（`rd-popover` の `hover` 属性）

## 目的

「押す前に少しだけ見せる」下見の面（プロフィール・リンク先の要約・用語の説明）。
shadcn の Hover Card に当たるものが無く、利用側が `mouseenter` と絶対配置で自作していた
（触れただけで出る・離れても消えない・キーボードで出せない、が繰り返し起きる）。

## なぜ新しい部品にしないか

骨格（トリガー + `[popover]`・非モーダル・`role="dialog"`・位置決め）は `rd-popover` と
**1 つも違わない**。違うのは「開くきっかけ」だけなので、属性 1 つで足りる
（ADR-0012 §6「部品の数を増やすほど保守が重い」）。`rd-tooltip` とも別物で、
中に押せるものが入る面は tooltip にできない（`role="tooltip"` は対話要素を持てない）。

## API

- `hover`（boolean、reflect）。既定 `false`。**初期化時にだけ**読む
  （後から属性を切り替えても購読は変わらない。動的に変えたいなら再マウントする）
- 見た目・`role` は変わらない。`popover.css` は 1 行も変えていない
- 契約にも `hover` を足したので、`markup({ hover: true })` と 4 ラッパーの
  `hover?: boolean` が同じ属性を指す

## 決めたこと

### 押して開く経路を残す

`popovertarget` の `<button>` はそのまま。**ホバーは近道でしかない**——
キーボード・タッチ・JS 無しでは今までどおりボタンが唯一の入口として働く
（ADR-0012 ティア B の約束を壊さない）。

### 遅延は開く 300ms / 閉じる 200ms

`popover.logic.ts` の `hoverTimings` に**数字を 1 か所だけ**置いた。
開くほうを長く待つのは、通り過ぎただけで面が出ないようにするため。閉じるのを待つのは、
トリガーから面へポインタが渡るあいだに消えないため（WCAG 1.4.13 Hoverable）。
`--rd-motion-duration-*` はトークンにあるが**読まない**——これは見た目の時間ではなく
操作の猶予で、`prefers-reduced-motion` でも縮めてはいけない。

### 開いてもフォーカスを奪わない

押して開いたときは今までどおり中の最初の行き先へ移す。**hover で開いたときは移さない**——
読んでいる人からフォーカスを取り上げると、そのあとの Tab の行き先が変わってしまう。
閉じるときも戻さない（そもそもトリガーに居ない）。区別は「この開閉が hover から来たか」の
フラグ 1 つで、状態は増やしていない。

### 離れたときに閉じるかは行き先で決める

`shouldCloseOnLeave(next, panel, trigger)`（純関数）。`relatedTarget` がトリガーか面の中なら
閉じない。`contains` だけを見る器で受けるので、実 DOM が無い node のテストでも回せる。

### タッチでは何も起きない

`pointerenter` は来ないか押下と同時に来る。**何も足さない**——押して開く経路があるので、
`@media (hover: none)` の分岐は要らない。

## a11y

- `role="dialog"` のまま（tooltip ではない。中に押せるものが入る）
- Esc はネイティブの light dismiss が閉じる。`popover` の値は変えない
- フォーカスでも開く（`focusin`）ので、ホバーだけに頼らない
- 面に乗っているあいだは閉じない（WCAG 1.4.13 Hoverable / Persistent）

## 代替案

- **`rd-hover-card` を新しく作る**: 骨格が `rd-popover` と同じなので、位置決め・契約・
  ラッパー生成・VRT がまるごと二重になる
- **`rd-tooltip` を拡張する**: `role="tooltip"` は対話要素を持てない。中にリンクを置いた時点で
  読み上げが壊れる
- **遅延をトークンにする**: 操作の猶予は「動き」ではないので `--rd-motion-*` に混ぜたくない。
  利用側が変えたくなったら `@cssprop` を足す（`rd-tooltip` の `--rd-tooltip-delay` と同じ形）
